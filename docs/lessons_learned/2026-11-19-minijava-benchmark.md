# MiniJava benchmark across six libraries

`Warpstone.Benchmarks/MiniJavaBenchmark.cs` parses the same MiniJava subset with Warpstone 1, 2 and 3 (two variants), Pidgin,
ParsecSharp and Parlot. The grammar, AST and inputs live in `Warpstone.Benchmarks/MiniJava/`.

## Setup that works

- All parsers build the same AST: records plus `Seq<T>`, a list with structural equality. Each parser is checked against the
  Warpstone 3 AST with `dotnet run -c Release --project Warpstone.Benchmarks -- verify-minijava`.
  Run that check after any grammar change, before you benchmark.
- The inputs are embedded resources named `MiniJava.<size>.java`. `large.java` is `medium.java` copied 10 times with the
  class names renamed (it was generated by a small Python script, see the git history).
- V1 and V2 were derived from the V3 file mechanically. The APIs differ in only a few places:
  - V2 has no `OptionalWhitespaces`, so it uses `Regex(@"\s*")`.
  - V1 `Maybe(p)` returns `IOption<T>`, so V1 uses `Maybe<T?>(p, null)`.
  - V1 and V2 use the `W.IParser<T>` alias. Without it, `IParser<T>` resolves to `Warpstone.IParser`, because that namespace
    encloses `Warpstone.Benchmarks`.

## Pitfalls

- The roslynaut `diagnostics` tool reported bogus `CS0518 System.String is not defined` errors for this solution.
  Use `dotnet build Warpstone.Benchmarks -f net8.0` instead. Loading the workspace also rewrote
  `src/Warpstone.Sources/packages.lock.json` for `net9.0` instead of `netstandard2.0`. Check `git status` and revert that file.
- `Parlot.SourceGenerator` compiles the whole project to run `[GenerateParser]` factories. Errors in any file surface as
  `PARLOT001 Emit failed ...` on `RightRecursiveSimpleString.parlot.cs`, followed by a misleading
  `CS8795 partial method must have an implementation`. The real errors are in the PARLOT001 message after the `;` separators.
- ParsecSharp 5 is written with C# 14 extension blocks. `using static ParsecSharp.Parser` does not import some of them as
  static calls, for example `SeparatedBy`. Call them as extensions (`p.SeparatedBy(sep)`).
- `Parsers.LeftAssociative` (Parlot) clashes with the `LeftAssociative<T, TInput>` type and with `Warpstone.Parsers`.
  Write `Parlot.Fluent.Parsers.LeftAssociative(...)`.
- Parlot `Else(null)` is ambiguous. Use a typed null, such as `Else((IExpr?)null)`.
- `Parlot.SourceGenerator` (the `Parlot_generated` benchmark) only accepts callbacks written inline in the
  `[GenerateParser]` method (error PARLOT003). The factory can't call another class's `Build()`, and lambdas can't live
  in generic helpers such as `Opt<T>`. That is why `ParlotGeneratedMiniJava.parlot.cs` holds a verbatim copy of
  `ParlotMiniJava.Build()`. Helpers that build parsers without lambdas (`Sym`, `Kw`) are fine.
- `Else(value)` with a non-constant value can't be generated (PARLOT005). Write `Else(static _ => Array.Empty<T>())` instead.
- Pidgin doesn't backtrack after consuming input. Multi-character symbols, keywords and identifiers (`Word.Assert`), the
  `[]` type suffix and local variable statements need `Try`.
- Farkle (an LALR parser generator, built at runtime in `FarkleMiniJava`):
  - Grammar build errors surface as `parser.IsFailing`, with the message in `Parse(...).Error`. `Verify` prints
    `GetBaseException()` so the message isn't hidden behind the `TypeInitializationException`.
  - Its regex dialect rejects escapes inside character sets (`[ \t]`) and an escaped `]`. Use the combinators instead:
    `Regex.Literal("[") + Regex.FromRegexString(@"\s*") + Regex.Literal("]")`.
  - Write `using Regex = Farkle.Builder.Regex;`, because a global using brings in `System.Text.RegularExpressions`.
  - `Nonterminal.Create(name, [.. productions])` with a collection expression can't infer `T`. Write `Create<string>(...)`.
  - `AsIs()` is obsolete (FARKLE1001). Use `AsProduction()`.
  - Conflict-free grammar: binary operators are left-recursive levels, the dangling `else` is split into closed and open
    statements, and `[]` is a single token, so that `int[] a` and `a[i]` don't need two tokens of lookahead.
- The BenchmarkDotNet filter matches `namespace.Class.Method`, so a filter must use `*MiniJavaBenchmark.Farkle`.
  `*MiniJava.Farkle*` matches nothing.
- `dotnet run` without a `--filter` (or with an unknown argument) makes BenchmarkDotNet wait for console input. Pass
  `< /dev/null`, or the command hangs until it times out.
- `--job dry` timings are cold-start (JIT) numbers. Use them only to check that nothing crashes.
