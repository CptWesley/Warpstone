# Left-recursion comparison (Warpstone vs. Guido/pegen vs. Umeda–Maeda)

Task: compare findings from an earlier claude.ai chat (Umeda & Maeda, JIP 29, 2021 vs. Guido van Rossum's left-recursive PEG article / pegen) against Warpstone's `GrowParser` implementation.

## Issues hit

- **claude.ai chat and share links cannot be fetched.** `claude.ai/chat/...` returns 403; `claude.ai/share/...` returns only the JS app shell. Ask the user to paste the content straight away.
- **`dotnet test -f net9.0` / `-f net8.0` failed restore** with `NU1102: Unable to find package System.Reflection.Metadata with version (>= 8.0.0)` (SDK 11.0.100 installed). `--no-restore` didn't help: `obj/project.assets.json` had no `net9.0` target.
- **That failed restore rewrote `src/Warpstone.Sources/packages.lock.json`** (netstandard2.0 → net9.0). Run `git status` after any `-f` restore and revert with `git checkout -- <lockfile>`.
- **Workaround for running probe code:** a scratch console project outside `src/` with `ImportDirectoryBuildProps=false`, `ImportDirectoryPackagesProps=false`, and `<Compile Include=".../src/Warpstone/**/*.cs" Exclude="Properties/**;obj/**;bin/**" />`. It builds without any packages. The DLLs in `bin/` were stale, so don't reference them.
- **Manual `Grow` placement (pegen style):** the leader must lie on *every* cycle, including direct self-loops. In `S ← A 'b' / 'b'; A ← A 'a' / S 'a'` the leader is `A`, not `S`. Picking `S` caused a hard `Stack overflow` that killed the process (Recursive mode), with no catchable exception.

## Results worth remembering

- Auto mode (default options) fails on indirect left recursion (`S/A`, `S/A/B`, interlocking cycles) because the analysis grows *every* cycle entry point it finds, and the inner growers' memo entries go stale.
- Auto grow and memo off, with one `Grow` on a pegen-style leader: `S/A` and `S/A/B` pass.
- `ParseOptions.Default` has `EnableAutomaticMemoization = false`. With it **on**, even Expr/Num (direct left recursion only) fails: the rule's subtree is reached via two paths, so inner nodes like `Seq(Lazy(num), digit)` get count 2 and a `MemoParser` inside the growing cycle, whose entry goes stale.
- Regression tests: `Warpstone.Tests/Expressions/LeftRecursionGrammars.cs`. 48 of 271 cases fail on purpose until left-recursion handling is fixed (indirect, interlocking, Expr/Num with memo on).
- Running them: scratch `lib/` + `runner/` pair (see [2026-11-19-legacy-test-port.md](2026-11-19-legacy-test-port.md)). A runner compiling only `Expressions/*.cs`, `Parsers/*.cs` and `Properties/GlobalUsings.cs` is enough and builds in seconds.

## pegen implementation (same day)

- `ILeftEdgeParser.AnalyzeLeftEdge` on every expression gives nullable + left-edge children. `LeftRecursionAnalysis` runs nullable fixpoint → Tarjan SCC → one leader on every cycle (prefers Lazy targets). It is called from `ParserBase.GetImplementation`, which no longer uses `RecursiveOccurrenceCounts`.
- Pitfall: skipping edges into explicit `Grow` nodes hid their cycles, so other members got auto-memoized and went stale. Keep the full graph for membership; treat explicit Grow nodes as pre-chosen leaders only for the acyclicity check.
- Sources snapshots can't be regenerated by tests while restore fails. Format = `//HintName: Warpstone.Sources.embedded.<dotted path>.cs` + `// <auto-generated/>` + `#pragma warning disable` + `#nullable enable annotations` + blank line + source (BOM stripped) + extra `\n`. A script reproduced the committed snapshots byte-for-byte modulo EOL; keep each file's existing EOL.
- Python text-mode read/write silently turns CRLF into LF. Use binary mode. Sort usings with `rstrip(';')` (SA1210).
- `dotnet build Warpstone` also rewrites `src/Warpstone/packages.lock.json`; revert it.

## Follow-up: memo bypass, linear analysis, Umeda–Maeda fallback (same day)

- **Explicit `Memo` in a left-recursive cycle** is bypassed in `GetImplementation` (`lookup[memo] = lookup[inner]`, following lazies and memo chains via `SkipBypassed`). It needs untyped access to the inner parser, so `MemoParser<T>` implements the internal `IMemoParser`. Mutation check: without the bypass, all 12 `Explicit_memo_*` cases fail.
- **Linear analysis:** `ParserAnalysisInfo.Heights` (internal) stores the longest path down from each finished parser, so a revisit only updates ancestor depths and does not walk again. A custom `IParserAnalysisInfo` still gets the old full walk (Sonar S3215 suppressed on that cast). `OccurrenceCounts` now counts references, not paths, so fewer auto-memo wrappers are added. Test: `AnalysisScaling` with 64 levels of `Or(p, p)`.
- **Leaderless cycles → `CycleGrowParser<T>` / `CycleGrowParserImpl<T>`** (Umeda–Maeda) on every non-lazy/memo/grow member. Per-position state (`InProgress`, `GrowRequested`, `Limits`, `Suspended`) is stored in the memo table under a shared `CycleGrowGroup` key, because parse contexts have no state bag and impls are shared across parses. The memo table is never enumerated, so that's safe.
- `Sources` snapshots can go stale through commits made outside the session (RegexParser/RegexParserImpl did). `scratchpad/snapcheck.py`-style full check: render every `src/Warpstone` file, compare EOL-insensitively, and list orphans.
- In Bash heredocs a doubled backslash in Python code arrives as a single one, which breaks string literals. Write scripts to a file with the Write tool instead.
